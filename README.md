## vas_logger

**Мониторинг адресного пространства процессов Linux с помощью kprobe-перехватчиков**

---

### Обзор

`vas_logger` — это модуль ядра Linux, который отслеживает запуск (`execve`) и завершение (`do_exit`) процессов, собирает информацию об их адресном пространстве и предоставляет к ней доступ через псевдофайловую систему `vas_log`.


### Возможности

- Регистрация системного вызова `execve` через kretprobe, что позволяет зафиксировать все сегменты памяти сразу после создания нового процесса.
- Обработчик `do_exit` через kprobe для удаления устаревших дампов при завершении процесса.
- Хранение собранных данных в хеш-таблице, индексируемой по PID.
- Управляемый через параметры модуля (`pid`, `dump_stat`) механизм запроса данных из пользовательского пространства.
- Безопасная работа с отложенными операциями через ворк-очереди (workqueue).


### Архитектура

Проект состоит из трёх логических компонентов, каждый из которых находится в своём подкаталоге:

| Компонент | Расположение | Назначение |
|-----------|--------------|------------|
| **Слой перехвата** | `src/hooks/` | Регистрация kprobe/kretprobe, сбор событий, планирование ворк-задач |
| **Слой хранения** | `src/storage/` | Хеш-таблица дампов, добавление/удаление записей, копирование для чтения |

Исходные файлы модуля:

- `src/main.c` – точка входа: инициализация хранилища, перехватчиков и файловой системы.
- `src/params.c` – параметры ядра: установка PID для наблюдения и чтение дампа по требованию.


### Сборка и установка

#### Требования

- Ядро Linux 6.14.
- Установленные заголовки ядра (`linux-headers`), компилятор GCC, make.

#### Сборка

```bash
make build
```

Команда вызовет `make -C /lib/modules/$(uname -r)/build M=$(pwd) modules`. В результате появится файл `vas_logger.ko`.

#### Загрузка

```bash
make run   # сборка (если требуется) и загрузка
```

Модуль также можно загрузить вручную:

```bash
sudo insmod vas_logger.ko
```

#### Выгрузка

```bash
make remove
# или вручную: sudo rmmod vas_logger
```

#### Установка в систему

```bash
make install
```

Файл модуля будет скопирован в `/lib/modules/$(uname -r)/extra`, после чего его можно будет загружать командой `sudo modprobe vas_logger`.

#### Другие полезные команды

| Команда | Действие |
|---------|----------|
| `make check` | Проверка состояния модуля (загружен, установлен, информация) |
| `make reload` | Перезагрузка (remove + build + run) |
| `make clean` | Удаление артефактов сборки |
| `make help` | Справка по всем командам |


### Использование

После загрузки модуля в системе появляется файловая система `vas_log`, смонтированная во внутреннее пространство ядра. Для получения дампа необходимо взаимодействовать с параметрами модуля через `sysfs`:

#### 1. Установка целевого PID

```bash
echo <PID> > /sys/module/vas_logger/parameters/pid
```

Замените `<PID>` на идентификатор интересующего процесса. Параметр только для записи.

#### 2. Получение дампа адресного пространства

```bash
cat /sys/module/vas_logger/parameters/dump_stat
```

Вывод будет содержать:

- Базовую информацию о дампе (PID, количество событий).
- Для каждого события `exec` – границы сегментов кода, данных, brk, стека, mmap_base, а также счётчики виртуальной памяти (`total_vm`, `data_vm`, `exec_vm`, `stack_vm`, `locked_vm`, `map_count`).

#### Пример вывода

```
=== Memory dump for PID 1234 ===
Number of events: 2

[exec] code: 0x400000-0x401000, data: 0x600000-0x601000, brk: 0x800000-0x801000, stack: 0x7fff0000, mmap_base: 0x7f0000000000
[exec] vm: total=10240, data=4096, exec=1024, stack=512, locked=0, map_count=15
```

#### 3. Удаление дампа

При завершении процесса (событие `do_exit`) дамп удаляется автоматически. Принудительно удалить информацию можно, выгрузив модуль (`rmmod`).


### Файловая система `vas_log`

Модуль регистрирует псевдофайловую систему с магическим числом `0x5641534c` ("VASL"). Она используется для внутреннего представления записей логов и не предназначена для прямого монтирования пользователем. Файловая система:

- Поддерживает до 1024 файлов с максимальным размером лога 10 КБ каждый.
- Предоставляет базовые операции чтения (`seq_file`), запись запрещена (`-EPERM`).
- Автоматически монтируется при загрузке модуля и размонтируется при выгрузке.


### Пример

В каталоге `examples/` находится простая программа `e1.c`, которая демонстрирует поведение `exec`. Скомпилируйте её:

```bash
gcc -o e1 e1.c
./e1
```

Программа печатает свой PID, после чего ожидает ввода:

- `N` — вызвать `execve` самой себя, создавая новое адресное пространство;
- `F` — завершить работу.

**Используйте этот пример для тестирования модуля:** загрузите модуль, запустите `./e1`, запишите её PID в `pid`, выполните `exec` нажатием `N` и получите дамп через `dump_stat`.


### Параметры модуля

Модуль регистрирует два параметра в `/sys/module/vas_logger/parameters/`:

| Параметр | Доступ | Описание |
|----------|--------|----------|
| `pid` | write‑only | Устанавливает целевой PID. Принимает целое число > 0. |
| `dump_stat` | read‑only | Читает дамп для PID, установленного в `pid`. |


### Внутреннее устройство

#### Хуки (kprobe/kretprobe)

- **`__x64_sys_execve`** – kretprobe, регистрируемый на функцию обработки системного вызова `execve`. После успешного возврата из вызова из структуры `mm_struct` извлекаются все параметры адресного пространства.
- **`do_exit`** – kprobe, срабатывающий при любом выходе из процесса. В обработчике планируется удаление соответствующего дампа из хранилища.

Оба обработчика используют ворк-очереди, чтобы не блокировать контекст ядра. Активные работы подсчитываются атомарным счётчиком, а при выгрузке модуля ожидается завершение всех операций через `completion`.

#### Хранилище

Данные хранятся в статической структуре `vg_st_storage`, содержащей хеш-таблицу (`DECLARE_HASHTABLE`) с 1024 корзинами. Ключом является PID процесса. Каждый дамп содержит двусвязный список событий (`list_head`). Поддерживаются операции:

- `vg_st_add_event()` – добавить событие (создаст дамп, если не существует).
- `vg_st_delete_dump()` – удалить дамп целиком.
- `vg_st_get_dump_copy()` – получить копию дампа для безопасного чтения из пользовательского пространства.

Доступ к таблице защищён спин-блокировкой `vg_htable_lock`.


### Совместимость

Модуль написан для ядра версии 6.14 . Использует следующие API:

- `kprobe` / `kretprobe`
- `work_struct` и `schedule_work`
- `DECLARE_HASHTABLE` и макросы хеш-таблиц
- `seq_file`
- `fs_context` файловых систем
- `kern_mount` / `kern_unmount`
- `module_param_cb`

Для работы необходима архитектура x86_64, так как используется символ `__x64_sys_execve`.
